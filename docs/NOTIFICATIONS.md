# 机器人通知配置

**简体中文** | [English](NOTIFICATIONS.en.md)

在扩展侧栏打开“设置 → 通知”。订单通知与告警通知分别选择渠道、填写配置并保存，可以分别使用飞书、钉钉、企业微信或 Telegram，也可以指向同一个机器人。

## 保持不变的通知规则

| 类型 | 何时发送 | 内容 |
| --- | --- | --- |
| 订单通知 | 真实成交核对成功后 | 币对、买卖方向、实际成交价、数量、USDC 价值、确认核对时剩余仓位、订单编号、交易哈希与确认时间 |
| 告警通知 | 登录凭据失效、接口失败等既有系统异常 | 异常说明与时间；同类告警五分钟内去重 |

价格触达、报价和交易提交不发送成交通知。订单通知在并发及后台重启后保持去重；更换平台不会重新发送已经处理的成交通知。未配置期间不积压待补发消息；订单与告警不互相回退。

选择“关闭通知”并保存即可关闭该类通知。也可以清空 Webhook；Telegram 需要同时清空 Bot Token 与 Chat ID。切换渠道会清空该类通知的表单输入，**保存后才生效**，不会影响另一类通知或交易开关。

消息使用当前中英文偏好。时间跟随运行扩展的系统时区并标注偏移，例如 `2026-10-21 07:30:00 GMT+08:00`，不根据界面语言切换时区。

## 测试配置连通性

1. 在对应通知类型下选择平台并完整填写配置。配置关闭、空白或格式无效时，测试按钮不可用。
2. 点击“发送测试通知”。**测试当前输入的草稿，无需先保存**，也不需要连接 FOMO、开启监控或真实下单。
3. 按钮显示发送中，并阻止该类重复点击；结果直接显示在该类配置下。接口成功表示平台接受消息，请同时检查目标聊天是否收到标记为“FOMO 通知连通性测试”的消息。
4. 若失败，按提示检查 HTTP 状态、平台错误码或网络。超时结果可能未知，请先检查收件，再决定是否手动测试；不会自动重试。
5. **测试成功后点击“保存通知配置”**，后续正式通知才使用此配置。修改配置后，旧测试结果会隐藏，需要重新测试。

订单通知与告警通知各有自己的按钮。测试消息只包含类型和时间，不冒充成交或异常，不创建订单、不修改交易开关、不保存草稿，也不占用正式成交去重或告警冷却。测试结果记录到操作日志，机器人凭据与平台原始响应不进入日志。测试请求不占用行情／交易命令队列。

## 飞书

1. 打开目标飞书群，在群设置的机器人入口添加“自定义机器人”。需要相应群权限；客户端菜单名称可能随版本变化。
2. 创建后复制完整 Webhook，在扩展对应通知类型中选择“飞书”并粘贴。
3. 如果机器人安全设置启用了“签名校验”，把该机器人的密钥填写到“加签密钥”；未启用则留空。
4. 如果启用了关键词校验，添加 `FOMO`。订单和告警正文都包含这个关键词，中文和英文模式均适用。
5. 点击“保存通知配置”。若订单和告警发往不同群，分别创建或配置两个机器人。

Webhook 格式（占位符，不能直接使用）：

```text
https://open.feishu.cn/open-apis/bot/v2/hook/<BOT_WEBHOOK_ID>
```

插件发送文本消息；加签按平台规范使用秒级时间戳、HMAC-SHA256 和 Base64。旧版已保存的订单、告警飞书地址会自动识别，无需重新输入。

[飞书官方：自定义机器人使用指南](https://open.feishu.cn/document/client-docs/bot-v3/add-custom-bot)

## 钉钉

1. 打开目标钉钉群的机器人管理，添加“自定义”机器人；需要群允许添加机器人。
2. 配置安全设置，使用“加签”，或设置自定义关键词 `FOMO`。若同时启用了多种校验，需要同时满足。
3. 复制完整 Webhook，包括 `access_token` 查询参数。
4. 在扩展选择“钉钉”，粘贴 Webhook。若启用加签，在“加签密钥”填入机器人设置中以 `SEC` 开头的密钥；仅关键词校验时可留空。
5. 保存配置。不要把自行生成的 `timestamp`、`sign` 拼进 Webhook 输入框；插件会在每次发送时自动生成。

```text
https://oapi.dingtalk.com/robot/send?access_token=<ACCESS_TOKEN>
```

插件发送文本消息。加签使用毫秒级时间戳，按平台规范计算 HMAC-SHA256、Base64 并编码签名。电脑系统时间错误也可能导致签名校验失败。

[钉钉官方：自定义机器人安全设置](https://open.dingtalk.com/document/robots/customize-robot-security-settings)

## 企业微信

1. 在企业微信群中添加“群机器人”，复制机器人 Webhook。此处使用群机器人，不是企业自建应用的消息接口。
2. 在扩展选择“企业微信”，粘贴完整 Webhook，包括 `key` 查询参数。
3. 保存配置。无需填写企业 Corp ID、应用 Agent ID 或应用 Secret。

```text
https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=<BOT_KEY>
```

群是否支持机器人取决于组织及群类型。需要机器人能在该群发消息；外部群等不支持的场景请以企业微信客户端为准。

[企业微信官方：群机器人配置说明](https://developer.work.weixin.qq.com/document/path/91770)

## Telegram

### 创建机器人与接收目标

1. 在 Telegram 找到官方 **@BotFather**，发送 `/newbot` 并按提示创建机器人，获取 **Bot Token**。请确认账号是官方 BotFather。
2. 按接收目标准备权限：私聊先向自己的机器人发送 `/start`；群聊先将机器人加入群并允许发消息；频道将机器人设为管理员并允许发消息。
3. 获取 **Chat ID**。它是聊天的数字标识，群／超级群通常以负数表示，例如 `-1001234567890`。公开频道也可使用 `@your_channel_name`。私人用户名不能替代私聊 Chat ID。
4. 在扩展选择“Telegram”，填写 Bot Token、Chat ID 并保存。两个字段必须同时填写，或同时清空。

### 获取 Chat ID

通过 Telegram 官方 Bot API 的 `getUpdates` 查询自己机器人的更新。下例只是接口格式，将占位符替换为你自己的 Token；不需要把 Token 提供给其他机器人或第三方查询网站：

```text
GET https://api.telegram.org/bot<BOT_TOKEN>/getUpdates
```

先在目标聊天中发送一条新消息。群里可发送 `/start@你的机器人用户名`，以便启用隐私模式的机器人也能收到命令。然后查看响应中 `result[].message.chat.id`；频道更新则查看 `result[].channel_post.chat.id`。示意：

```json
{
  "ok": true,
  "result": [
    {
      "message": {
        "chat": { "id": -1001234567890, "type": "supergroup" }
      }
    }
  ]
}
```

更新为空时先发送新消息再查询。若机器人已配置接收消息的 webhook，`getUpdates` 无法同时使用；请从现有集成获取 Chat ID，或使用专用于本扩展的机器人。不要为查询 ID 删除正在使用的集成。插件只调用 `sendMessage`，不会轮询或消费你的更新，也不会修改机器人的 webhook。

插件通过官方 `api.telegram.org` 发送纯文本，不启用 Markdown／HTML 解析；代币名称中的特殊字符无需转义。运行扩展的网络需要能访问 Telegram Bot API。

[Telegram 官方：BotFather](https://core.telegram.org/bots/features#botfather) · [getUpdates](https://core.telegram.org/bots/api#getupdates) · [sendMessage](https://core.telegram.org/bots/api#sendmessage)

## 排错与凭据保存

| 现象 | 检查 |
| --- | --- |
| 完全没有通知 | 是否保存；该类是否关闭或留空；事件是否满足原有通知规则；订单是否已经通知过 |
| 保存失败 | 所选平台与 Webhook 域名／路径是否一致；地址是否完整；Telegram 两个字段是否有效且成对填写 |
| 飞书／钉钉拒绝消息 | 机器人关键词是否包含 `FOMO`；是否启用了加签但未填写正确密钥；若启用 IP 白名单，当前网络出口是否被允许 |
| 企业微信拒绝消息 | Webhook 是否对应可用的群机器人；机器人是否被移除；是否触发平台频率限制 |
| Telegram 失败 | Token 是否有效、Chat ID 是否正确、私聊是否启动、机器人是否在群内且有发消息权限、当前网络是否可访问官方 API |
| 日志显示发送失败或结果未知 | 查看平台配置和网络。HTTP 200 也可能是业务失败；超时不能证明消息未送达，插件不自动重发成交消息 |
| 更新扩展后不可用 | 在 `chrome://extensions` 重新加载，若 Chrome 提示新增通知域名权限，按提示确认；随后重新打开侧栏 |

Webhook、加签密钥、Bot Token、Chat ID 保存在当前扩展的本地 IndexedDB，输入中的凭据默认隐藏，不发送到 FOMO，不进入订单／日志导出。只向所选平台的官方 HTTPS 机器人接口发送通知，禁止请求重定向。平台原始异常与响应不写入日志，发送失败不递归触发告警。

本扩展不提供后台服务器；浏览器关闭后仍停止监控和发送通知。`config/local.example.json` 只说明配置结构，不会自动加载；实际配置以扩展设置页为准。
