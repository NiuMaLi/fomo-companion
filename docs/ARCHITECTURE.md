# 架构与订单恢复

## 建议目录

```text
entrypoints/
  background.ts             # 调度、持久化、行情、执行权
  fomo.content.ts           # 隔离世界与页面桥接
  sidepanel/                # 单账户交易面板
  options/                  # 告警、参数、配置导入
src/
  adapters/fomo/            # HTTP、认证、行情、报价、签名、确认
  trading/                  # 状态机、触发、风险检查、数量预留
  storage/                  # IndexedDB、迁移、事务
  notifications/            # 飞书、告警队列、脱敏
  shared/                   # 类型、消息协议、金额计算
  components/               # 表单、价格与状态展示
config/
docs/
tests/
```

独立服务未来与扩展共享 trading、协议和金额规则，但使用单独的认证、存储与签名适配器；当前不把它加入可选可用模式。

## 信任与运行边界

- 页面负责经过验证的认证／钱包操作；后台负责交易授权策略、持久化和执行调度；侧边栏展示数据及用户输入。
- 严格限制到 FOMO 站点与必要接口域的权限，真实可用域名以验证结果为准。避免全站点 host 权限。
- 所有触发先检查全局开关、账户、连接和报价新鲜度，再检查金额、预留量及交易内容。
- 页面消息不得直接绕过后台风控进入签名或广播。后续必须审查页面桥接是否能被站点脚本伪造。
- 同一账户同一资产的执行串行化；同一条件单使用持久化 compare-and-set 争用执行权。仅有 JS 内存锁不足以跨重启防重。
- 多标签页只能选一个认证／签名页面，其他页面不创建独立执行器。
- 页面与后台断联时保留订单、停止提交；电脑睡眠不能保证触发时效。

## 订单与执行记录

订单至少保存 ID、版本、账户绑定、networkId、tokenAddress、方向、条件类型、目标价、价格基准、数量快照、卖出比例、互斥组、创建时间、状态及暂停原因。

执行记录单独保存订单版本、执行意图 ID、预留资金／数量、报价摘要及期限、签名／交易哈希、provider intent ID、广播状态、确认状态、错误分类及时间戳。

金额和数量以十进制字符串或最小单位整数保存，不以二进制浮点做金额决策。不持久化私钥或钱包恢复材料。

## 状态流

```text
等待触发 → 已认领 → 报价与校验 → 等待签名 → 已签名待提交
                                             ↓
                          待核对 ← 提交结果不明／已提交
                            ↓                ↓
                     已确认失败         已确认成交
```

等待状态可取消、暂停。已认领但尚未广播的执行需要取消令牌与版本检查。签名完成后、广播前再次检查关闭开关与订单版本；对可能已经广播的交易不能承诺取消成功。

网络超时、浏览器崩溃和 provider 状态不明统一进入待核对，保留资产预留。只有证据确认旧交易不可能再成交后才能释放并允许重建交易。

同一已签名交易的重广播与创建另一笔交易是不同操作：前者仍需确认签名、有效期与全局停止策略；后者在旧结果不明时禁止。

## 重启恢复

1. 读取全局开关、数据库版本与待恢复记录，迁移失败时暂停执行。
2. 获取当前账户与钱包能力，确认与订单绑定一致；账户变化时暂停旧订单。
3. 对已签名、已提交、待核对的记录，以交易哈希、provider ID、平台历史和余额等证据核对。
4. 核对完资金和数量预留，再获取新鲜行情与报价。
5. 自动交易原为关闭则保持关闭；失联或异常恢复后需要展示清楚原因。
6. 电脑休眠期间可能错过价格穿越。恢复后不凭旧价格补单，依据新鲜价格重新判断仍有效的条件，并显示恢复状态。

## 开关语义

关闭开关必须先持久化，再让界面显示已关闭；后台不再创建新执行意图。已经广播的交易继续核对，等待单保留。关闭操作失败应显示失败，不能仅切换按钮颜色。

开启前检查认证、钱包、行情和待核对记录。第一版按钮至少展示：已关闭、检查中、运行中、已暂停及具体原因。

独立服务未来启用时需增加执行权 epoch／租约与 fencing 校验，以及一个唯一的提交出口；仅租约超时不足以阻止旧实例提交。模式切换必须先完成旧实例停止与未完成交易核对。


## v0.4.0 当前实现

- `background.ts` 管理单一活动 FOMO 页面和账户授权；`coordinator.ts` 在 IndexedDB 事务中认领订单，按账户串行执行。
- `page-executor.ts` 将认证、钱包和未签名／已签名交易保留在页面闭包；`wallet.ts` 从当前 React Provider 的形状发现站内钱包，不依赖 minified 名称或远程模块 hash。站点变化时能力检查失败关闭。
- `quote.ts` 校验网络、原子单位、真实余额、滑点、目标价与执行路线；`solana-transaction.ts` 保留 legacy/v0/v1 原始 message，合并代付和用户签名，逐个 Ed25519 验签。准备阶段先做无状态链上预检。
- 后台发 prepare、sign；取得哈希后先持久化 signed，再允许 submit。MAIN 只接受固定业务协议，不导出 Token、签名材料或私钥，不接受任意 URL／任意消息签名。
- 关闭／切换账户通过 revoke 标记已有 attempt，并用 generation 使进行中的准备失效；异步高度查询、钱包签名返回后与提交前再次核对撤销、账户、价格及有效期。
- 准备中重启标记失败；signed/submitted 重启进入 unknown。unknown 只查询旧哈希，并冻结该账户新执行；未实现基于最终区块证明的自动过期解除。
- `receipt.ts` 核对成功链上回执和本钱包资产／USDC 余额差，记录实际成交量与价。SOL 叠加 native/WSOL 变化，并在本人付费时排除交易费；实际租金退款等边界仍需实盘核验。
- 成交、日志和通知意图在事务中写入；只有核对确认成交才发订单通知。空通知地址直接完成处理，不补发未配置期间的成交。
- IndexedDB v4 归档 v3 waiting 单并关闭两个开关，保留通知配置。更早版本仍清理 paper 状态、标记历史模拟记录。
- 页面和活动条件单分别订阅行情；View.prices 按资产键提供逐单当前价，历史不再订阅的价格显示过期。

单元测试证明调度和编码规则；真实报价及预检已通过，钱包实际签名、广播和真实成交闭环尚待验收。原生全量成交历史、互斥止盈止损和浏览器退出长期恢复未完成。页面 MAIN 与网站共享信任边界，页面内脚本可见业务桥接，不能作为隔离恶意站点脚本的安全沙箱。


## v0.5.0 附带保护与通知

Draft.protection 保存可选两侧价格和比例，只允许限价买入；Order.parentOrderId／ocoGroupId 关联子单。coordinator 在父单确认的同一 orders+logs 事务内，按 fillQuantity 创建稳定 ID 的子单。重启不会重复生成。预留计算对互斥组取最大数量，普通订单逐单相加。账户级数据库认领在 preparing／signed／submitted／unknown 时阻止下一笔；一侧确认后在同一事务取消仍等待的另一侧。取消命令也使用事务比较状态，避免取消与认领并发覆盖。

订单保存 remainingQuantity，来源为确认后同币全部链上钱包账户只读查询，通知恢复复用保存的快照。成交通知价格、数量和价值来自回执；旧记录未知字段不补造。订阅在确认事务后立即同步，买单转成保护单时继续订阅本币。

本次不修改数据库版本和迁移，不清理用户已有订单、开关或 Webhook。本地最低额校验已移除，正值／精度／余额校验和平台报价拒绝保留。

## v0.6.0 多链

page-executor 根据 /swaps/v3 的来源选择直接 Solana 或 native-runtime；后者发现当前页面原生模块、检查接口和钱包身份，EVM 使用智能账户 UserOperation，Solana 使用单次执行。Coordinator 先保存执行意图，再发 execute-native；progress 仅更新哈希。routed-receipt 按来源请求 ID／UserOperation 恢复及真实成交 signature 精确匹配核对。未知结果不重试下单。数据库仍为 v4，新增字段为可选，无清数据迁移。


## v0.7.0 日志快照与语言

`Log.order` 为可选白名单快照：只取公开资产标识与订单事实，排除账户／钱包／执行上下文；原因先脱敏再保存。创建、触达、取消、签名、提交、失败、成交及保护单日志保存各自事件状态。协调器日志在写入前重读已更新订单，成交及保护日志仍与订单在同一事务提交。旧日志不回填假历史；详情层可回退到当前订单并标注来源。

`settings.language` 默认 `zh-CN`，允许 `en`；独立命令合并保存。IndexedDB 仍为 v4，无清库或开关重置。面板 localStorage 只缓存语言以减少首次绘制闪烁，后台设置为权威来源。翻译在显示／通知时进行，持久日志正文不改写；动态旧日志按已知模板匹配，未知内容保留原文。日志导出保留原始 message，同时附 displayMessage 与语言元数据。


## v0.8.0 逐单滑点

`Draft.slippageBps` 为可选整数（0～500，单位 bps）。新建单将缺省值持久化为 0，表示关闭；协调器只读取订单值，不读取旧 `Settings.slippageBps`。旧设置字段仅兼容读取，无默认值，旧全局编辑命令已移除。保护单继承父单值。日志快照白名单增加滑点，旧快照缺失显示未记录。

关闭时 prepare 的可选滑点参数为空、`/swaps/v3` 请求省略 `slippageBps`，两个报价解析入口均不将 0 当成零容忍。开启时沿用平台返回滑点不超过本单上限与保守报价校验；关闭后限价目标仍检查预期报价，止损无本地报价偏离上限。平台构建交易中的固有限制不可由插件关闭，签名校验和报价有效性／余额／5%价格影响校验不受影响。数据库仍为 v4。
