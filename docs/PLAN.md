# 需求与实施计划

> v0.5.0：已实现买入附带互斥止盈止损及完整成交消息，本地金额门槛已移除；本轮仅确定性与 UI 验证，实盘保护验收仍未完成。

> v0.4.0：已实现逐单当前价与 Solana 网络真实报价、签名、广播、确认代码。4U SOL 报价、编码和链上预检已验证；尚未执行真实签名或买卖闭环，M3 的实盘完成条件仍未满足。下面的旧阶段内容为历史计划；模拟引擎已移除，独立服务未开放。

## 已确认需求

- 目标为 `https://fomo.family`，仅支持单账户。
- 展示余额、持仓、估值、订单与历史成交；提供快速交易和实时行情。
- “现价单”修正为限价单。若平台没有原生挂单接口，采用本地价格触发后报价、签名、提交的条件单；这不保证按目标价成交。
- 卖出比例为 30%、50%、100% 和自定义比例，与目标价独立。
- 输入目标价和点击价格快捷按钮后，显示相对最新价的涨跌幅；有可靠成本数据时额外显示相对持仓成本的涨跌幅，并标明基准。
- 订单、设置和执行记录需要持久化，重启浏览器后恢复。
- 增加自动交易开启／关闭按钮。独立服务模式在认证和签名能力验证通过后开放。
- 登录异常触发可配置的飞书告警。
- 面板支持已适配网络的有效 FOMO 代币详情页；行情随当前页面切换，K 线选价回填目标价。
- 持仓显示真实头像、平均买入价和未实现盈亏。
- 实盘测试仅允许 SOL，本次测试 SOL 持仓不超过 10U，其他既有代币不参与测试。

## 运行能力决策

| 模式 | 第一版安排 | 边界 |
| --- | --- | --- |
| 浏览器和 FOMO 页面在线 | 优先实现 | 依赖页面认证、钱包就绪状态；失联暂停提交 |
| 浏览器打开但 FOMO 页面关闭 | 待验证 | 行情和数据库可独立，但认证／签名尚无可用闭环 |
| 关闭浏览器，独立服务运行 | 能力预留，暂不可用 | 需要独立续期和合法可用的签名器；复制 Token 不够 |
| 电脑关机、休眠或断网 | 无法实时执行 | 持久在线主机可作为后续部署方式，仍受认证／签名限制 |

“自动交易关闭”停止创建新的执行意图，保留等待中的条件单，并继续核对已提交交易。重新开启先同步账户、核对未完成记录，再决定是否恢复触发。

## 实施阶段与完成条件

当前 v0.2.0 已实现工程骨架、页面只读适配、侧边栏、订单数据库和单条件模拟执行。30 项测试与生产构建通过，打包页面脚本已在 document_start 读到真实账户、BTC 行情和头像，并通过真实 K 线点击选价。完整扩展安装链路、浏览器实际退出恢复、历史分页、互斥组、真实交易及告警仍需后续完成，不能将本版本称为实盘完成版。

### M0：只读协议调研（已完成）

完成余额、历史交易 GET 请求和 SOL 价格 WebSocket 的只读验证；记录认证与签名依赖、最小交易配置及未验证事项。详见 [验证记录](fomo/VERIFICATION.md)。

### M1：工程骨架与只读插件

采用 TypeScript、React、WXT、Chrome Manifest V3。实现侧边栏、设置页、消息协议、账户适配层、行情适配层、IndexedDB 仓储及配置校验。

先验证页面桥接能稳定获取当前账户标识、登录健康状态和钱包能力。页面桥接不能依赖固定 hash 的模块文件名，也不能将调研工具当作插件运行依赖。以实际权限和运行环境验证跨域 Cookie 请求，不把调研成功等同于扩展后台成功。

完成条件：可安装到 Chrome；能只读查看账户和当前代币行情；重开面板后数据正常；失联、无登录态和过期行情有明确状态。

### M2：条件单引擎与模拟执行

实现限价买卖、止盈止损、卖出比例、目标价涨跌幅、金额检查、数量预留、互斥、审计记录及崩溃恢复。先接模拟执行器，以确定性测试证明行为正确。

完成条件：重复价格推送、并发触发、关闭开关、页面失联和重启恢复均不会导致新的重复执行意图。模拟结果不能称为真实成交验证。

### M3：浏览器交易适配

验证报价接口金额单位、资金来源代币、签名入口、交易编码和确认机制。调用签名前校验交易中实际资产、金额、目标账户和费用上限，避免只校验界面表单。

必须先持久化交易签名／交易哈希，再广播交易；提交结果不明时进行链上和平台核对。FOMO 的服务端幂等能力尚未验证，不能承诺 exactly-once。

完成条件：能在允许范围内跑通真实 SOL 买入、卖出及成交核对；对应 API、签名和失败响应补充到文档。

### M4：告警、打包与恢复验收

实现飞书告警、脱敏、冷却、持久化重试队列及配置导入。完成浏览器真实重启、后台回收、断线重连、暂停／恢复与设置迁移验证。

完成条件：交付可安装包、源码、安装说明、配置示例和测试结果；所有未支持能力在界面中明确标识。

### M5：独立服务可行性验证

只有在无需页面也能刷新认证，且能够通过明确授权的签名机制执行交易时才实现。不得以导出私钥、助记词或复制浏览器钱包内部恢复材料作为默认方案。

如可实现：本机服务受保护通道、单实例执行权、开启／关闭命令、服务存活状态和账户绑定必须同时交付；切换模式不能产生双执行器。

## 交互规则

- 涨跌幅公式：`(目标价 / 基准价 - 1) × 100%`；使用明确标注的“较现价”和“较成本”。
- 目标价固定，行情变化时更新“较现价”数值，显示行情新鲜度。
- 限价买单 `价格 <= 目标价`；限价卖单 `价格 >= 目标价`；止损卖单 `价格 <= 目标价`。
- 止盈与止损区分方向，不能统一实现成价格大于等于目标价。
- 选择比例时显示预计卖出数量和金额。创建时将卖出数量落实为持仓快照对应数量；自动重启不重新扩大数量。用户后续加仓不自动扩大既有卖单。
- 同一持仓的止盈止损可组成互斥组，先预留数量；一侧进入执行流程后另一侧暂停，成交后按实际卖出量核减。结果不明期间不释放预留。
- 金额不足、行情过期、账户切换、签名不可用时暂停并给出原因，不自动改变比例或补买。
